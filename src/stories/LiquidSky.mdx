# For LiquidSky developers

This page is for anyone building `@maropost-ui/liquidsky-ui` to the Marobase design. LiquidSky names
its components `App*` (used in many places), `The*` (one per app) and `MpV*` (Vuetify wrappers).
Marobase names everything `Mp*`. The tables below give each LiquidSky name its page here.

**{count('matched')}** LiquidSky names have a full design here, **{count('partial')}** have part of one,
and **{count('no-reference')}** have none yet.

## How to find a design

1. **Look up your component** in the tables below, then open the linked story.
2. **Every docs page that is a LiquidSky reference** starts with an *In LiquidSky* line naming your
   components. To see only those pages, open the sidebar's tag filter and pick `liquidsky`.
3. **Show code** under a story gives the Vuetify markup and props that produce what you see.
4. **Values come from tokens, not from the screenshot.** Every size, gap, radius and colour is a token
   in `src/design-tokens/tokens.json` (the file LiquidSky already copies). *Foundations* shows the
   scales, and *Foundations › QA Reference* names the token behind each measured value.
5. **Themes:** the toolbar's *Theme* switch is Light / Dark. LiquidSky's `marobaseLight` is our Light
   and `marobaseDark` is our Dark. Marobase has no Classic theme.

## Names that work differently

- **`AppBar` and `AppSidebar` here are one-per-app parts.** In LiquidSky they would be `The*`: AppBar is
  `TheHeader`, AppSidebar is `TheUnifiedNavigation`. They sit under *Patterns › App Shell*.
- **No `MpV*` wrappers here.** Marobase styles plain Vuetify components through the theme defaults and
  global styles. Where your `MpV*` wraps a Vuetify component, its design is the story for that
  component (for example `MpVBtn` is *Foundations › Buttons*).
- **Icons:** Marobase uses Lucide names (`settings`, `chevron-down`); LiquidSky uses MDI. A short list
  of MDI names and the Lucide icon each one maps to is under *Foundations › Icons › MDI aliases*. There
  is no full map yet.

## Design review

This list is the same one design review uses. *Foundations › QA Reference* shows the measured values
for each matched part, and `docs/qa/` describes the review process. To change a mapping, edit
`src/stories/qa/liquidskyMap.ts`; this page and the *In LiquidSky* lines update with it.
